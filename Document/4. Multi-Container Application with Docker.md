# 1. Module Introduction

A multi-container application separates application components into individual containers.

Instead of running everything inside a single container:

```text
Frontend
Backend
Database
```

Each service runs independently.

Benefits:

- Better scalability
- Easier maintenance
- Independent deployments
- Improved security
- Easier debugging

# 4. Dockerizing PostgreSQL Service

PostgreSQL can be run directly from the official Docker image.

Pull the image:

```bash
docker pull postgres
```

Run PostgreSQL:

```bash
docker run -d \
  --name postgres-db \
  -e POSTGRES_USER=admin \
  -e POSTGRES_PASSWORD=password \
  -e POSTGRES_DB=mydb \
  -p 5432:5432 \
  postgres
```

---

## Using a Volume

To persist database data:

```bash
docker volume create postgres-data
```

```bash
docker run -d \
  --name postgres-db \
  -v postgres-data:/var/lib/postgresql/data \
  postgres
```

Benefits:

- Data survives container deletion.
- Safe database storage.

# 5. Dockerizing Node.js Application

Example backend structure:

```text
backend/
├── package.json
├── package-lock.json
├── src/
└── server.js
```

Create a Dockerfile:

```dockerfile
FROM node:20-alpine

WORKDIR /app

COPY package*.json ./

RUN npm install

COPY . .

EXPOSE 5000

CMD ["npm", "start"]
```

Build image:

```bash
docker build -t backend-app .
```

Run container:

```bash
docker run -d -p 5000:5000 backend-app
```

---

## Environment Variables

Pass variables securely:

```bash
docker run -d \
  -e DATABASE_URL=postgresql://user:password@postgres-db:5432/mydb \
  backend-app
```

# 6. Dockerizing Next.js Application

Create Dockerfile:

```dockerfile
FROM node:20-alpine

WORKDIR /app

COPY package*.json ./

RUN npm install

COPY . .

RUN npm run build

EXPOSE 3000

CMD ["npm", "start"]
```

Build image:

```bash
docker build -t frontend-app .
```

Run:

```bash
docker run -d -p 3000:3000 frontend-app
```

---

# 7. Running Next.js with Bind Mount

During development, rebuilding the image after every code change is inefficient.

Use bind mounts:

```bash
docker run -it \
  -p 3000:3000 \
  -v "${PWD}:/app" \
  frontend-app
```

Benefits:

- Instant code updates
- Faster development workflow
- No image rebuild required

# 8. Adding Security Layer for PostgreSQL Container

Database containers should never expose unnecessary access.

---

## Strong Credentials

Avoid:

```text
admin
password123
```

Use:

```text
POSTGRES_USER=my_secure_user
POSTGRES_PASSWORD=very_secure_password
```

---

## Environment Variables

Store secrets in:

```text
.env
```

Example:

```env
POSTGRES_USER=admin
POSTGRES_PASSWORD=securepassword
POSTGRES_DB=appdb
```

Run:

```bash
docker run --env-file .env postgres
```

---

## Limit Network Access

Instead of exposing PostgreSQL publicly:

❌

```bash
-p 5432:5432
```

Prefer internal Docker networking:

```text
Backend → PostgreSQL
```

without exposing the database to the internet.

---

## Use Custom Networks

Create network:

```bash
docker network create app-network
```

Run database:

```bash
docker run -d \
  --network app-network \
  --name postgres-db \
  postgres
```

Run backend:

```bash
docker run -d \
  --network app-network \
  backend-app
```

Now only containers inside the network can access PostgreSQL.
